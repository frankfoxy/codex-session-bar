# Memory Watch · 内存排查

Windows 原生 Rust 托盘程序，默认每 30 秒采样一次，可选择 15、30、60、120、300 秒。

- 查看物理 RAM、系统提交内存、开机提交峰值、分页池及非分页池。
- 按进程或按程序名称汇总显示 Private、RAM、单次增长、观察后增长、CPU、句柄及线程。
- 点击列标题排序；筛选名称或 PID；选择进程查看路径、内核池及提交峰值。
- 关闭/最小化窗口只隐藏到托盘。点击托盘图标恢复，右键可暂停、立即采样、打开日志或退出。
- 每次采样保存全部进程，刷盘后更新 latest.json。日志在工作区 tmp/memory-watch-rust；当前 samples.jsonl 达到约 16 MiB 后，旧日志自动压缩为 .jsonl.gz，保留最近 7 份压缩归档。
- 旧版未压缩日志会自动转换；压缩后逐字节校验，成功后才移除原文件。归档可用 7-Zip 等工具解压后分析。
- 普通内存监测只读，不清理内存、不调整分页文件或驱动。新增 Codex Git 防护仅在验证归属和查询命令后自动处理超限 Git；不会结束 Codex 本身或其他应用。

## Codex Git 内存防护

默认开启，**每 5 秒**检查一次，独立于普通内存记录的 30 秒周期；暂停记录不暂停防护。默认上限为 **64 个 Codex Git、私有提交内存合计 4 GiB**。在 Session Bar 的 **Session details → Codex Git memory protection** 可开关，无需填写参数。

只识别当前用户、当前 Windows 会话内，祖先进程可追溯到已安装 Codex Desktop/CLI 或 VS Code Codex 扩展的 `git.exe`。执行前重新采样并检查 PID、创建时间、可执行路径、用户身份、祖先链和 Git 命令。只自动结束 `diff`、`status`、`log` 等已识别的查询命令；提交、推送、克隆及未知命令跳过，归属不明的进程跳过。仅为分类读取 Git 的命令行，不写入完整命令行或会话内容。

超限复核后优先处理占用高的查询进程，将触发指标降到上限的约 80%，每次最多 512 个。检查是周期性的，进程数和内存可能短暂超过上限。若仅有写操作或无法验证的进程，弹窗提示并保留记录。告警窗口独立运行，不阻塞采样和后续防护；同类连续告警最多每分钟弹出一次，日志仍记录每次处理。

工作区 `tmp/memory-watch-rust/` 中的相关文件：

- `codex-git-guard-settings.json`：默认开关和上限；高级用户可修改 `max_processes`、`max_private_mib`，5 秒内读取。数量允许 8–4096、内存允许 256–65536 MiB；配置错误时停止自动处理并告警。
- `codex-git-guard-status.json`：心跳、检查耗时、数量、合计内存、处理计数及错误，Session Bar 读取该状态；失联时明确显示不可用。
- `codex-git-guard-events.jsonl`：触发原因、目标及 Codex 祖先 PID/创建时间、查询类型、内存和处理结果。先记录并刷盘，再执行结束；日志不可写时停止处理。
- 防护事件日志达到约 1 MiB 时压缩旧文件，逐字节校验后删除原文，保留 5 个 `.jsonl.gz` 归档。

防护由 Memory Watch 独立进程执行；Session Bar 可后台启动打包的伴随程序，关闭 Session Bar 后已启动的防护继续运行。退出 Memory Watch 会停止防护；Session Bar 开着且开关开启时会尝试恢复。Windows 登录后的启动由 Session Bar 的自动启动任务负责。

运行 `bin/memory-watch.exe`。从源码构建：运行 `Build.ps1`，需要 Rust MSVC 和 Visual Studio C++ Build Tools。

Private 是私有提交内存；RAM 是驻留在物理内存中的部分。它们并不相同。CPU 为两次采样间按全部逻辑处理器归一化的平均值。首次采样无增长基线；PID 与创建时间共同识别进程，避免 PID 重用造成假增长。汇总峰值为本次监测期间观察到的组峰值。

每次日志写入完成后调用刷盘，但突然断电/硬件故障仍可能导致最后一条丢失；30 秒采样也可能漏掉更短的尖峰。不要仅凭当前占用最大就判定根因。
